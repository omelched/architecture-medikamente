# Задание 6

## Входящие данные

- выгрузки из 1С (финансы, склад)
- данные операционных сервисов (ПД, медкарты, расписания, платежи)
- файлы в S3 (результаты анализова - сканы, PDF, Excel)

## Правила и классификаторы

- regexp (паспорт, ИНН, телефоны)
- ML-модели BigID для обнаружения ПД/медданных в текстах
- тегирование уровня чувствительности (ПД, Медданные, Финансовые, Внутренние).

## Преобразование данных перед классификацией

- нормализация форматов (даты, телефоны, кодировки)
- очистка от дублирующихся записей
- унификация схем для табличных данных
- OCR для PDF/сканов
- предварительная валидация и стандартизация полей.

## Cлой анализа конфиденциальности

- отдельный модуль (BigID) получает доступ к данным из разных сервисов
- присваивает теги чувствительности и типы данных
- Airflow маршрутизирует объекты в соответствующие слои хранилища:
  - RAW — необработанные данные
  - PROTECTED — токенизированные/зашифрованные
  - TRUSTED — обезличенные
  - GOLDEN — агрегированные витрины.

## Хранение

- теги BigID хранятся в метаданных Apache Airflow
- после классификации - структуруированные данные хранятся в managed postgresql в разных узлах СУБД в зависимости от тега

## Масштабирование

- BigID масштабируется горизонтально (HPA k8s)
- Airflow масштабируется за счет Managed Aiflow от клауд-провайдера
- витрины DWH масштабируется за счет Managed Postgesql, S3
