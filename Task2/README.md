# Задание 2

## Описание новых блоков

### Сервис аутентификации

Приложение keycloack, аутентифицирует пользователей связанных сервисов, выдает JWT токены.

### Identity Providers

AD FS - хранит оргструктуру, RBAC/ABAC сотрудников.
Yandex ID - IdP для клиентов, удостоверяет личность.

### Сервис "Регистратура"

Управляет только расписанием посещений. Реализует API для client-app, по управлению собственными записями. Реализует веб-интерфейс для просмотра Врачами и упарвлением сотрудником регистратуры. По интеграции с keycloak может предоставить идентификатор клиента, у которого есть визит "в моменте", для предоставления доступа к карточке. Не хранит персональные данные клиента, историю болезни, кроме токенизированного идентификатора клиента.

### Сервис "История болезни".

Хранит и предоставляет историю болезни по идентификатору клиента, не хранит персональные данные. Хранит результаты визитов, результаты анализов, назначения и т.д. Реализует API для просмотра клиентом своей истории болезни через client-app и для получения карточки в веб-сервис-регистратуру для врачей. Реализует веб-интерфейс для сотрудника регистратуры по созданию новых карточек (но не просмотру).

### Сервис client-app

Клиентское приложение для просмотра своих записей к врачам и истории болезни. Идентифицирует клиента по yandex Id, предоставляет доступ только к собственным записям и карточкам по ABAC.

### Аналитичекий стек

Apache Airflow - оркестрирует обработку данных из нескольких источников, предоставляет витрины данных для аналитиков.

BigID - инициализируется Apache Airflow, тегирует данные, маскирует персональные данные клиентов перед перечачей в витрину Apache Airflow.
