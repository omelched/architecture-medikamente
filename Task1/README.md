# Анализ безопасности системы

## Конфиденциальные данные, которые не учтены во внутренних системах

### Неучтенные данные

Персональные данные:

- Заполненные бумажные анкеты пациентов (хранение без учета и аудита)
- Скан-копии паспортов и полисов ОМС/ДМС в общей папке
- Телефоны/почты клиентов, пересылаемые сотрудниками по корпоративной почте
- Личные медицинские жалобы/описания симптомов от клиентов в переписке

Медицинские данные

- Результаты анализов, лежащие в Excel-файлах и отправляемые лабораторией по почте
- Сканы медицинских карт (PDF/JPG) без контроля доступа
- Внутренние заметки врача, хранящиеся локально на его ПК

В компании выявлено два процесса:

- основной (обслуживание клиентов)
- вспомогательный (обслуживание ТМЦ и расчетов)

## Аудит мер по обеспечению безопасности данных

Проблемные зоны в текущем подходе к управлению данными:

- нет классификации данных
- нет журналирования
- нет резервного копирования медданных (файловый сервер — единая точка отказа)
- отсутствие минимизации данных
- Хранение разных категорий данных "в одной файловой системе".
- Отсутствие RBAC/ABAC на чтение конфиденциальных данных.
- Отсутствие методов защиты данных (обфускация, маскирование) при хранении персональных данных клиентов.
- Отсутствие возможности горизонтального масштабирования хранилища данных.
- Отсутствие отказоустойчивости и катастрофоустойчивости в хранении критически-важной для основного процесса информации.

## Что можно улучшить

| Объект данных                                      | Методы защиты                                         |
| -------------------------------------------------- | ----------------------------------------------------- |
| ПД клиентов                                        | Шифрование, токенизация, маскирование                 |
| Медданные (результаты анализов, диагнозы, анамнез) | Токенизация, раздельное хранение, шифрование в покое  |
| Связка ПД + медданные                              | RBAC/ABAC                                             |
| Финансовые данные                                  | Шифрование, раздельное хранение ПД и платежных данных |
| Документы сотрудников                              | Шифрование + DLP в почте                              |

| Объект данных  | Проблема                                                                              | Решение                                                                                             |
| -------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Журнал приемов | Сотрудники ресепшн имеют полный доступ к журналу приемов                              | ABAC/RBAC политики уровня "только на создание записи"                                               |
| ПД клиентов    | Сотрудники ресепшн имеют полный доступ к личным делам пациентов                       | Минимизация данных, необходимых для создания нового приема (только ФИО)                             |
| ПД клиентов    | Мед.специалисты имеют полный доступ к личным делам пациентов                          | Ограниченный доступ к личному делу пациента / результату анализа "только во время активного приема" |
| ПД клиентов    | Мед.специалисты (сотрудники лаборатории) имеют полный доступ к личным делам пациентов | Токенизация клиентов в записях результатов анализов                                                 |
| Все            | Отсутствие возможности горизонтального масштабирования для открытия нового отделения  | Шардирование данных (привязка клиентов к отделению)                                                 |
| Все            | Отсутствие отказоустойчивости и катастрофоустойчивости                                | Выбор облачного провайдера, соответствующего 152-фз, перенос хранилища в облако                     |

## Тегирование данных

### Классы данных

- ПД — персональные данные
- Медданные — медицинские данные
- Финансовые — финансовые данные
- Внутренние — внутренняя служебная информация

### Применение

- таблицах СУБД (не пересекать в одной таблице данные разных классов)
- объектам в хранилище (S3)
- витриным в DWH

Сохранение тегов в metadata-каталоге BigID + Apache Airflow.
